# p2p-peer-reputation-go

本地可运行的 P2P 节点信誉评分与连接治理服务。节点通过内存总线模拟点对点连接，
转发交易与区块消息；服务按节点行为进行信誉评分，并据此执行断开、限流与封禁。
所有治理状态持久化到本地磁盘，进程重启后状态连续。

## 运行

```sh
go run . -dir ./data     # 运行端到端演示（评分→封禁→观察期→重启恢复）
go test ./...            # 运行全部自动化测试
```

## 架构

```
main.go                    演示程序：完整生命周期 + 崩溃恢复演示
internal/govern/           治理内核（确定性、可持久化）
  types.go                 消息、判定、决策、参数等基础类型
  clock.go                 Clock 接口：真实时钟 / 手动时钟（测试用）
  score.go                 按 (节点, 主题) 维护的评分表，指数时间衰减
  ban.go                   封禁、指数退避、观察期状态机
  store.go                 文件存储：WAL（JSONL）+ 原子快照
  engine.go                事件引擎：评分+封禁+去重+恢复的唯一状态转移入口
internal/p2p/              网络模拟与治理网关
  transport.go             内存消息总线（模拟回环连接）
  node.go                  节点：身份、发送、接收
  service.go               治理网关：连接配额、限流、洪泛防护、指标
```

## 评分模型

每个 `(节点, 主题)` 对独立维护一个分数（默认范围 `[-100, 100]`，初始 0）。

| 事件                     | 权重（默认） |
|------------------------|------------|
| 有效且及时的消息          | `+1`       |
| 有效但超时（>5s）的消息    | `-0.5`     |
| 无效消息                 | `-10`      |
| 重复消息                 | `-1`       |
| 超量（被限流）的消息       | `-2`       |

- **时间衰减**：分数按半衰期（默认 1 小时）向 0 指数衰减，
  `score *= 0.5^(elapsed/halfLife)`。旧行为的影响随时间消退。
- **封禁阈值**：分数 `<= -20` 时触发封禁，连接被断开。
- **观察期加成**：观察期内所有负权重乘以 `ObservationPenaltyFactor`（默认 2 倍）。

## 治理语义

**封禁与退避**：触发封禁后，该 `(节点, 主题)` 进入封禁期，期间消息直接在入口
丢弃。封禁时长按违规次数指数退避：`base * 2^(offenses-1)`，上限 30 分钟
（第 1 次 1 分钟，第 2 次 2 分钟，第 3 次 4 分钟……）。封禁期满进入观察期
（默认 2 分钟）：惩罚加倍、限流速率减半；观察期无违规后恢复正常。

**主题隔离**：评分与封禁按 `(节点, 主题)` 独立维护。节点在 `blocks` 主题上
被封禁，不影响其在 `txs` 主题上的中继与评分。

**连接配额与限流**：

- 单节点身份的同时连接数受 `MaxConnsPerPeer` 限制，超出拒绝。
- 每节点独立令牌桶（`RatePerSecond` + `Burst`），超量消息被限流并记为
  `excess` 扣分；观察期内速率减半。
- 全局限流桶保护总处理带宽。

**洪泛防护**：节点必须先消耗自己桶中的令牌才能占用共享处理预算，因此洪泛
节点在入口即被丢弃，不会挤占正常节点的带宽与队列；接收方收件箱有界，溢出
丢弃。所有防护动作通过 `Service.Metrics()` 可观测
（`Throttled`/`FloodDrops`/`Rejected`/`Bans` 等计数器）。

**持久化与崩溃恢复**：

- 每个事件先写 WAL（append + fsync）再应用，崩溃不丢已确认事件。
- 每 `SnapshotEvery` 个事件写一次原子快照（临时文件 + rename）并截断 WAL。
- 恢复 = 加载快照 + 顺序重放其后的 WAL；事件带单调序号，已入快照的事件
  不会被重复应用。
- 消息去重集合（带 TTL）随快照持久化：重启后同一消息仍被识别为重复，
  不会因恢复重放而重复计分。

**动态加入与离开**：节点离线后连接槽位被回收；重新加入的节点按身份绑定
的历史评分继续受治理——封禁记在身份与主题上，更换连接无法规避。

**确定性**：引擎是单线程事件处理器，所有时间来自注入的 `Clock`，无随机源，
无依赖 map 遍历顺序的逻辑。给定相同的 `Params` 与事件序列，各节点评分变化
与连接决策逐次一致（见 `TestDeterminism`）。

  确定性重放。

  校验器判无效、重连无法规避封禁、未连接拒绝、端到端收发、重复洪泛惩罚。
